Big-picture product goal:
The final public Shiny app should allow a user to:
1. Open YTAB Shiny app.
2. Point the app to a FASTQ directory.
3. Choose a species/reference from resources/species/.
4. Let the app detect samples.
5. Review/edit the sample sheet.
6. Run the full local pipeline from alignment to final results.
7. Explore normalization interactively.
8. Compare treated vs untreated libraries.
9. Export tables, plots, and reports.

Architecture:
- Shiny = user interface, project setup, plots, tables, progress display, result exploration.
- Python modules = computational backend.
- Shiny should call Python CLI wrappers using system2() or processx, not reimplement the pipeline in R.
- Pipeline steps should write config files, logs, manifests, CSV/TSV/JSON outputs, and plots.
- Shiny should read those outputs and display them.
- Long-running alignment should not happen directly inside a reactive expression without a controlled process wrapper.

Bowtie2 index rules:
- A complete Bowtie2 small index requires all six files:
  <prefix>.1.bt2
  <prefix>.2.bt2
  <prefix>.3.bt2
  <prefix>.4.bt2
  <prefix>.rev.1.bt2
  <prefix>.rev.2.bt2

- Also support Bowtie2 large indexes:
  <prefix>.1.bt2l
  <prefix>.2.bt2l
  <prefix>.3.bt2l
  <prefix>.4.bt2l
  <prefix>.rev.1.bt2l
  <prefix>.rev.2.bt2l

- If complete .bt2 index exists, return:
  bowtie2_index_complete=True
  bowtie2_index_type="bt2"
  bowtie2_index_prefix=<prefix without .1.bt2 extension>

- If complete .bt2l index exists, return:
  bowtie2_index_complete=True
  bowtie2_index_type="bt2l"
  bowtie2_index_prefix=<prefix without .1.bt2l extension>

- If no complete index exists, return:
  bowtie2_index_complete=False
  bowtie2_index_type=None
  bowtie2_index_prefix=None
  warning: "No complete Bowtie2 index found. Indexing will be required before alignment."

Thread logic:
- detected_cpu_count should use os.cpu_count() or 2.
- If detected CPU count is less than 2, validation should fail with:
  "YTAB local pipeline requires at least 2 CPU threads."
- default_threads:
  detected = os.cpu_count() or 2
  if detected < 2:
      raise RuntimeError("YTAB local pipeline requires at least 2 CPU threads.")
  default = max(2, min(4, detected))
  if max_threads is provided:
      default = min(default, max_threads)
      if default < 2:
          raise RuntimeError("YTAB local pipeline requires at least 2 CPU threads.")
  return default
- User-selected threads:
  must be >= 2
  should be <= detected CPU count
  may be > 4 if the machine has >4 CPU threads
- Validation error if threads < 2:
  "threads must be >= 2 for local YTAB runs"
- Validation error or blocking warning if threads > detected CPU count:
  "requested threads exceed detected CPU count"
- Add a non-blocking warning if threads > 4:
  "Using more than 4 threads may increase memory use on low-memory machines."

create_project_config should:

- Discover FASTQs using discover_fastqs().

  output/projects/<PROJECT_ID>/

- Store sample sheet entries in the YAML or reference the sample_sheet.csv path.
- Store resolved reference information, including Bowtie2 index prefix and whether index is complete.
- Use relative paths where possible, but support absolute paths.

validate_project_config should check:
- FASTQ dir exists.
- At least one sample has include=True.

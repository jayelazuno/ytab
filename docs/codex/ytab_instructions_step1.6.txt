Goal:
Add a clean reference preparation layer before alignment. The app and CLI should be able to check whether a selected species has a usable reference. If Bowtie2 indexes are missing but a FASTA exists, the pipeline should be able to build the Bowtie2 index as an explicit reference-preparation step. Do not hide index building inside the alignment algorithm.

Important design:
- Bowtie2 index is built from FASTA only.
- GFF/GTF/feature_table are used for feature annotation and SummaryTable, not for Bowtie2 indexing.
- If complete Bowtie2 indexes already exist, skip indexing.
- If FASTA exists but Bowtie2 indexes are missing, allow the user to build indexes with a separate prepare-reference command.
- If FASTA is missing, do not attempt indexing. Show a clear error telling the user to restore/download/provide reference FASTA.
- Do not restrict YTAB to only the species currently in the repo.
- Species discovery should support future user-added species.
- Do not delete existing outputs.
- Do not modify scientific algorithms.
- Do not run alignment.
- Do not use qsub or HPC paths.

Species discovery rules:
- list_available_species() should not list every folder blindly.
- A folder under resources/species/<name>/ should be considered a selectable species only if:
    resources/species/<name>/reference_genome/ exists
    AND it contains at least one likely reference file:
      *.fna, *.fa, *.fasta, *.gff, *.gff3, *.gtf, *feature_table*.txt, or *chromosomal_feature*.tab

Definitions:

- can_be_prepared:
    FASTA exists
    AND at least one of GFF, GTF, or feature_table exists
    Bowtie2 index may be missing
- runnable:
    FASTA exists
    AND at least one of GFF, GTF, or feature_table exists
    AND Bowtie2 index is complete

Warnings:
- FASTA missing:
    "Reference FASTA missing. Cannot build Bowtie2 index."
- annotation missing:
    "No GFF/GTF/feature table found. Feature annotation will not be available."
- index missing but FASTA present:
    "No complete Bowtie2 index found. Run reference preparation before alignment."
- index complete:
    "Bowtie2 index found; indexing skipped."

Add src/ytab/pipeline/reference_prepare.py

Implement:
    build_bowtie2_index(fasta: Path, index_prefix: Path, threads: int = 2, force: bool = False) -> dict
    ensure_fasta_index(fasta: Path, force: bool = False) -> dict
    prepare_reference(species: str, repo_root: Path | None = None, threads: int = 2, force: bool = False) -> dict

Behavior:
- Resolve the species using reference_registry.resolve_reference().
- If complete Bowtie2 index already exists and force is false, skip index building.
- If index is missing and FASTA exists, run:
    bowtie2-build --threads <threads> <fasta> <index_prefix>
- Choose index_prefix as FASTA path without final FASTA suffix.
  Example:
    GCA_014217725.1_ASM1421772v1_genomic.fna
  gives:
    GCA_014217725.1_ASM1421772v1_genomic
- If FASTA .fai is missing, run:
    samtools faidx <fasta>
- If GFF exists and gffutils DB is missing, do not force DB generation yet unless current YTAB code already has a known safe utility for it. Instead write a warning:
    "gffutils DB missing; DB generation will be added in a later reference-prep step."
- Write:
    resources/species/<species>/reference_genome/reference_prepare_manifest.json
- Manifest should include:
    species
    fasta
    index_prefix
    bowtie2_index_complete_before
    bowtie2_index_complete_after
    fasta_index_created
    commands_run
    warnings
    timestamp

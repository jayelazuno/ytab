# YTAB Shiny shell

`run_app.R` resolves the repository relative to its own location. The landing page supports new-project initialization through `shinyFiles`, dynamic existing-project discovery, and an optional demonstration project. Every workspace command uses one validator-backed active `project.yaml` path.

The workspace uses horizontal application tabs and nested stage tabs. Opening a project or changing a tab never runs scientific work. Raw SummaryTable success is the analysis-ready boundary; MidLC remains in Essentiality and raw-summary CPM remains in Fitness Screen.

FASTQs are never uploaded. Pasting a directory path is the quickest option for large or network-mounted storage; local folder browsing is also available. Choosing a directory does not scan it. **Scan FASTQs** explicitly performs one nonrecursive top-level scan, limited to 5,000 preview entries. Matching outer quotes are removed from pasted paths, while internal spaces are preserved. Execution uses raw `processx` argument vectors, and quoting is applied only to human-readable command previews.

Preprocessing sample selection is interactive and persists across nested tabs. Project-level `include` values remain read-only; stage selection is temporary. Presets cover included, parent, treated, incomplete, failed, and none. Each core stage presents selected/completed/remaining/failed counts and a per-sample status table. Raw SummaryTable success for every included sample defines analysis readiness. Repository-relative built-in references are resolved from the repository root, and a complete existing Bowtie2 index is never rebuilt merely by opening or refreshing the workspace.

MapFastq, CreateHitFile, and SummaryTable use item-level persistent progress; LibraryDiagnostics reports reliable phases. Progress JSON is written atomically beneath `manifests/jobs`, and the current-job pointer supports progress recovery after the app is reopened. Confirmed item completions determine the progress bar. Approximate ETA uses the median current-run duration per input byte when sizes are available, otherwise median item duration; it is unavailable until the first non-cached completion. The global active-job banner polls every 1–1.5 seconds, while log panels retain only recent stdout/stderr lines. Cancellation preserves completed work and permits cache-aware resume.

Workspace tabs and nested preprocessing tabs use explicit stable values. **Change sample selection** navigates to the Samples tab while retaining selection; **Continue preprocessing** chooses the next dependency-valid tab; **Enter analysis browser** opens Quality Control → Mapping QC; and **Switch project** returns to landing without cancelling a running external job. Dry-run progress is explicitly validation-only: validated items may reach 100%, while executed and scientifically completed remain zero. Finished summaries can be dismissed from the session without deleting durable progress or logs.

Quality Control is implemented in `R/ui_qc.R`. Mapping and raw Summary QC use compact principal tables, with file paths and secondary summary metrics in collapsed details. Library Diagnostics owns a separate persistent QC selection and offers all eligible, parents, treated, clear, and custom selection. Preview and real execution are explicit; Force is a cache-bypass control only. Cache manifests are sample-set and input-hash aware, run-specific outputs are retained, and the shared job manager presents phase-level progress without fabricated item ETA. Concise result summaries keep full commands, stdout/stderr, hashes, and paths inside collapsed **Technical details**. Diagnostic Files provides a typed inventory and existing-plot cards without changing or regenerating scientific plots.

`R/qc_result_state.R` separates the live selector, a hash-validated matching result, and the latest historical result. Legacy unsigned manifests remain discoverable but cannot be labeled matching. Library Diagnostics uses three compact workflow sections, with sample review and Technical details collapsed by default. Diagnostic Files caches one inventory per session/project and invalidates it only after refresh, project change, or diagnostics completion. File-table and plot-gallery modes are exclusive; the gallery is image-only, filterable, paginated at eight cards, lazy-loaded, and uses a local modal without reading images into R memory or regenerating them.

The Fitness Screen keeps Design, Run Analysis, and Results separate. Generated valid comparisons are searchable and temporary selection persists between those tabs without changing `comparison_design.csv`. Analysis IDs are generated and editable only under Advanced settings. Preview, real execution, cached reuse, Force cache bypass, Keep-going behavior, and optional classifier annotation are explicit. Fitness always uses raw SummaryTable inputs and CPM inside the established R analysis. Results distinguish matching, historical, and legacy output and offer existing-call summaries, filtering, stable-file downloads, a call chart, and an effect-versus-z plot. Technical provenance remains collapsed; no P values or volcano plot are added.
